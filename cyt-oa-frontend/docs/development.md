# 开发说明

## 本地启动

```sh
npm install
npm run dev      # http://localhost:4810
```

前端只做代理转发，不带后端地址的构建期常量：`vite.config.ts` 把 `/admin-api`、`/api`
代理到 `VITE_PROXY_TARGET`，默认 `http://127.0.0.1:48081`。

本服务固定使用 `48081`（后端）+ `4810`（前端），`strictPort` 已开启：端口被占用时直接报错，
不会静默跳到 4811。`8189/8190` 是 CYT-Common 的一对，`8080/8081` 属于网盘，不要混用。

## 检查

```sh
npx vue-tsc --noEmit    # 类型检查
npm run build           # 类型检查 + 构建，CI 里等价于这道命令
npm run test:navigation  # 目录归属、权限与分批上线回归
```

## 页面是怎么拼起来的

- `src/configs/pages.ts` 声明每一个台账页：接口地址、列、字段与操作按钮。
  新增一张后台表通常只在这里加一项，不需要写新组件。
- `src/configs/nav.ts` 声明左侧导航的区块、一级项与二级项；二级项是带查询参数的路由，
  所以同一个视图的不同标签在地址栏是可分享的。
  已有业务按设计稿的名称、顺序、层级与彩色图标排列；辅助能力集中到「管理工具」总览，仍保留原有权限、上线 key 和搜索入口。
  `glyph` 是设计稿中的原始图标，未填写时沿用原业务图标，不按名称猜测替换。
  目录组合继续引用原菜单的权限和上线 key；有额外操作权限的入口必须同时满足原业务权限。
  查询参数较具体的入口优先选中，面包屑与快速搜索使用同一份目录，避免多个子项同时高亮。
  `sidebarParent` 将页签归并到同一侧栏入口；权限裁剪后没有主入口时，保留可访问的独立入口。
  人事侧栏按工作台、招聘、花名册、入离职与合同、生命周期收敛为 5 项；面试、在职/离职分类和合同模板放在页内切换。
  人事功能融合在门户「管理中心 → 人事管理」中，进入任何人事页面都保留原侧栏及两级菜单，不切换到独立导航。
  人事工作台四项概况与花名册真实筛选联动；试用分类使用 `statusCategory=2`，列表与导出沿用同一筛选。
  招聘概况由职位、候选人状态统计和待面试接口分别读取；部分失败显示独立错误与「—」。阶段、职位状态、面试结果、搜索和分页保存在 URL，刷新和返回后保留。
  桌面点击父级标题展开并进入默认子页，箭头单独展开/收起；手机抽屉点击父级先展开，选择子页后关闭抽屉。父级与当前子页分别高亮。
  仅持有 `hr`（可同时有 `employee`）角色的账号仍按权限只展示「人事管理」及其子菜单，登录后进入人事工作台。
  HR 专用账号的旧书签、个人资料和非人事回跳定向至首个已授权的人事页面；账号菜单隐藏个人资料，业务接口仍独立校验权限。
- `src/pages/DataPage.vue` 消费上面两份声明，渲染表格、筛选与表单。
- 只有交互特殊的页面（个人中心各视图）才单独写组件。

字段的下拉选项来自后端字典接口，见 `src/lib/dict.ts`；不要在页面里硬编码枚举，
除非该枚举只用于前端展示分支。

## 接口与身份

请求统一走 `src/lib/api.ts`（管理端）与 `src/lib/me-api.ts`（个人中心）。
会话令牌、身份与权限判断集中在 `src/lib/session.ts`，路由守卫据此把非管理员挡在控制台外。

## 样式与组件

设计系统基于 Tailwind CSS 4 + Reka UI 无头组件，按 shadcn-vue 的组织方式维护：

- `src/styles/theme.css` 是唯一全局样式入口：设计令牌（颜色、圆角、动效）与
  `panel`、`data-table`、`field-label` 等组合类都在这里定义，深色模式走 `.dark` 类。
- `src/styles/workspace.css` 由主题入口导入，维护响应式外壳、工作台双栏、登录页与快捷入口。
  桌面侧栏支持收起和二级浮出菜单，移动端使用导航抽屉；个人办公与获授权的管理中心入口统一呈现。
- `src/ui/` 是基础组件（Button、Dialog、Select、Badge、Pagination、EmptyState…），
  用 `cn()`（clsx + tailwind-merge）合并类名、`cva` 声明变体。
- 导航和工作台保留设计样例的彩色图标，集中在 `NavIcon.vue` 映射；操作图标用 `@lucide/vue`，
  提示统一用 `src/lib/toast.ts` 的函数式 toast。

新增页面优先组合 `src/ui/` 组件与 `theme.css` 的组合类，不要退回原生控件或另起一套
按钮/卡片样式；颜色一律引用语义令牌（`bg-card`、`text-muted-foreground` 等），
不要写死十六进制色值。

视觉以设计提供的[企业门户样例](https://share.traecontent.cn/artifact/1D5NTD5VGTOBUD)为准：
浅色侧栏上方放身份卡，内容使用淡紫灰背景、白色面板和紫色强调，工作台使用紫色欢迎区。
默认浅色，保留用户保存的主题偏好；深色模式通过同一套语义令牌适配。
公共菜单图标固定为 16px，菜单项最小高度 36px，危险操作使用语义红色，
菜单、下拉选项和弹窗统一层次、圆角、键盘焦点和关闭交互。
业务页面复用语义令牌，不叠加装饰性光晕；指标必须来自接口，加载失败使用「–」或错误提示，
不可把失败结果显示成零。工作日历 `WorkCalendar.vue` 提供月份切换和回到今天，
它只展示日期，不隐含业务事件或考勤安排。

表单控件需要关联 label、输入 ID 与校验消息；Select 和 MultiSelect 将附加属性转发到实际触发按钮。
界面变更应检查 1440px 桌面与 390px 窄屏、深色模式、搜索跳转、二级菜单和弹窗关闭，
联调时不要为验证界面而提交真实审批、考勤或通讯录同步操作。

员工生命周期沿用人事 demo 的员工列表与详情布局，桌面列表高度随视口调整，
移动端限制列表高度，让详情可以在下方展开。窄列表使用 `Pagination compact`，
通用分页根据容器空间换行；统计文字不换行，不能用窗口断点假定容器足够宽。
历程与合同在同一详情面板内切换，搜索、状态、页码、所选员工和详情视图保存在 URL，
刷新后保留上下文。布局验证须覆盖 177 人、9 页、长姓名及部门、空记录和接口报错。

## 个人中心功能树对齐

- 员工目录统一提供首页、大促新品、申请审批、申领记录、报告、条件开放的团队数据、四类发声渠道、目标 OKR 与个人资料。直属团队、指定审批人与站点负责人条件在 `personalizeNavigation` 中统一处理，搜索和面包屑使用同一结果。
- `src/pages/workspace/` 提供 OKR、发声与问卷、门户申请、规则和团队考勤页面，接口集中在 `/api/workspace`。新管理入口 `portal-voice`、`portal-workspace-rules` 纳入原上线开关目录，继续独立校验业务权限。
- 企微单据保留 `/me/apply`；新门户申请使用 `/me/requests`，有草稿、审批链、撤销和审批记录。采购与用章从办事入口进入门户流程，流程未启用时不能提交。报销标准按费用类别限制单次金额；请假跨年分别占用额度。
- 述职报告使用 `/me/review-reports`，独立存储草稿、提交和直属上级点评，不将旧日报/周报/月报接口虚构为支持 `type=4`。
- `/me/records` 按页签读取本人考勤、培训进度、已送达贺卡及申领记录。物资审批记录限定登录账号负责的站点；团队考勤的人员范围由后端推导，全公司范围仅系统管理员可用。
- 新业务依赖数据库迁移 `V20261111_003__portal_workspace_features.sql`。开发检查没有执行共享库升级，交付时随既有数据库迁移流程发布。
- 与原型仍有明确边界：晋升自动贺卡、可编辑的个人祝福文案、公司动态定时发布尚无完整业务链路；现有页面不提供伪成功操作。自定义数据范围目前用于 OKR 与门户审批，首页及旧工作报告继续遵循既有组织关系。问卷可编辑全员或指定员工范围；原型中按部门发放的配置入口尚未接入。
