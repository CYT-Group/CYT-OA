# 人事工作区

> 数据库使用 PostgreSQL，初始化和升级统一通过 `src/main/resources/db/postgresql/migration/` 的版本迁移。
> 操作见[后端 README](../README.md#3-建表与初始数据)与[数据库规范](../src/main/resources/db/postgresql/migration/README.md)。

人事入口位于「管理中心 → 人事管理」。按提供的 `hr-system.html` 接入招聘、花名册、入离职、合同模板和员工生命周期；员工与组织继续使用现有 HRM 数据。

## 页面与复用范围

- `/hr/workbench`：复用 HRM 首页的人事概况、招聘统计、待办和人事日程；明细可跳转办理页或带筛选条件的员工列表。
- `/hr/recruit?tab=candidates`：复用 HRM 候选人新增、阶段流转、淘汰、候选人转员工。简历原件通过受权接口上传和下载，每人最多 5 份，每份最多 10MB，支持 PDF、DOCX。
- `/hr/recruit?tab=interviews`：复用 HRM 面试安排与结果反馈服务，增加跨候选人的面试分页查询，保留原有轮次和状态流转校验。
- `/hr/recruit?tab=posts`：复用 HRM 招聘职位查询和新增。
- `/page/hrm-employee?roster=active` 和 `?roster=left`：复用原员工档案页，增加在职/离职筛选、部门筛选、受权导出、生命周期入口与离职证明。完整资料与转正、晋升等原有任职操作继续保留。
- `/hr/employment?mode=onboard`：新增员工、已有待入职档案、招聘候选人三种来源。生成文书后核对并确认签订；员工变更、HRM 合同登记、文书归档在同一事务提交。候选人转员工复用原 HRM 服务，已有企微档案的身份、部门、岗位、入职日期不能在此覆盖。
- `/hr/employment?mode=offboard`：复用 HRM 离职类型、原因和日期规则，归档签订文书。当天或历史离职即时停用关联账号；未来离职按北京时间每 5 分钟检查生效。取消离职或发生再入职后，旧文书不再触发停用。本人及系统管理员账号受现有账号服务保护。
- `/hr/templates`：提交版本、审核、预览和下载。DOCX、PDF、UTF-8 TXT 可提取正文，形成文本模板；原文件排版不作为生成模板保留。通过模板变量生成文本，可下载 TXT 或经浏览器打印为 PDF。公司既有 Word 合同生成入口继续保留。
- `/hr/lifecycle`：汇总真实入职日期、任职变更、已归档绩效、文书与合同登记。计划变更与已生效变更分别展示，不生成虚构绩效或交接记录。离职证明只从完整的离职档案与签约公司生成，需单位核对盖章。

## 数据库与授权

工作区结构与权限种子已纳入 `src/main/resources/db/postgresql/migration/` 的初始版本，由部署流程中的 Flyway 在更新应用前执行。全新环境从空库执行全部版本即可；后续变更新增版本文件，不修改已执行的迁移。

新增三张表：`hrm_contract_template`、`hrm_employment_document`、`hrm_candidate_attachment`。员工和候选人不另建副本。已有员工合同仍写入 `hrm_employee_contract`。

脚本为内置 `hr`、`admin` 角色补齐本次使用的 HRM 权限及后台入口。HR 可招聘、维护员工和提交模板；模板审核仍要求系统管理员。角色管理、全员导出和通讯录同步不包含在此次 HR 授权中。自定义人事角色可按业务需要分配同名权限，不能仅凭菜单可见性授权接口。

每次确认签订附带请求编号与签订资料摘要。相同操作者、相同资料的重试返回原归档结果；复用编号提交其他资料会被拒绝。审计只写动作及业务编号，不写证件、薪资或文书正文。

先应用数据库升级，再部署并重启后端，重新登录以刷新前端权限。随后提交公司现行模板，由系统管理员审核后用于办理。此次开发未向现有业务库应用升级，也未部署服务。

## 验证

后端运行 `mvn test`；新增测试覆盖模板变量、重复提交、资料摘要、HRM 失败时停止归档、审核权限及取消/变更离职后的账号停用边界。前端运行 `npm run build`、`npm run test:navigation` 和 `npm run test:portal-rollout`。

数据库检查使用一次性 PostgreSQL 测试库，验证初始化、授权范围、事务回滚及生命周期/面试 SQL。连接与执行方式见[开发说明](development.md#测试)。Playwright 以模拟接口验证招聘跟进、入离职确认、花名册刷新、归档读取、错误状态，以及 1440px、390px 和深色模式。此检查不等同于实际后端的完整联调。
