# Portal 后台管理与 HR 管理迁移

> 数据库使用 PostgreSQL，初始化和升级统一通过 `src/main/resources/db/postgresql/migration/` 的版本迁移。
> 操作见[后端 README](../README.md#3-建表与初始数据)与[数据库规范](../src/main/resources/db/postgresql/migration/README.md)。

Portal 的后台管理与 HR 管理由 OA 承接，员工展示门户继续保留。源仓为 `D:/code/CYT-Portal`，OA 管理中心为 `/portal`。

## 管理入口

- 后台管理：管理中心、角色权限、AI 配置与版本、数据分析、新闻、知识库、品牌手册、样品与办公用品、培训、批量导入、展会、新品、分类与 API 成本。
- HR 管理：20 类块文档编辑与版本（含高级 HTML 块）、签收统计与催签、劳动合同、庆祝日历与贺卡、员工庆祝日期、简历识别与面试。
- 原 `can_*` 能力位继续使用。`can_enter_admin` 可登录 OA 管理入口，系统管理入口仍限 OA 管理员；角色授权和 AI 密钥不能通过矩阵转授给非管理员。
- 合同使用原 DOCX 模板；品牌 HTML 在不带同源权限的 sandbox 中预览；简历与上传文件经 OA 鉴权读取。公共图片和随机 token 贺卡仅公开其展示内容。

## HR 文档工作台

按用户后续要求，保留原门户完整编辑功能，并按 OA 的界面与交互重组展示层：列表、编辑和预览均留在 Shell 导航内、当前标签页切换，返回保留筛选。列表使用 OA 的 PageHeader、控件、数据表与更多菜单，列和行操作对齐；编辑分开页头主操作与工具栏，保留纸张、大纲和设置，正文的封面、章节配色和主题保持真实阅读效果。

支持块间插入与搜索、20 类块、逐块预览、富文本与表格、编辑/分栏/预览三态、拖动调宽与滚动同步、封面/主题/目录/PDF/签收设置、草稿历史预览/恢复/删除，以及智能排版的文件/粘贴/当前内容入口。排版任务支持进度、结果预览、应用、撤销、失败重试与删除；应用结果只进入本地编辑器，保存和发布仍需用户明确操作。

兼容层只转换接口元信息的命名，并将 OA 的安全整数字符串 ID/人数转回原组件所需的数值；`blocks`、`cover`、`signoff` 等内容结构原样保留，避免破坏 `activeTab`、`subHeader`、`button_text` 等混合命名字段。新建文档补存块失败时保留本地正文。引用摘要使用员工读侧接口，保留封面、主题与默认说明；旧 `/article/{id}`、`/hr-doc/{slug}` 和切流参数兼容到 OA 预览/编辑。

异步排版任务按提交人隔离，每人每小时 20 次（重试计入），保留原提示词和块校验。服务重启或历史迁移中的未完成任务标记为失败，允许用户手动重试，不自动重放付费调用。后台 worker 显式携带提交人用于审计，不依赖请求线程登录上下文。

发布校验对嵌套 JSON 递归规范化，避免 JSON 键顺序变化导致保存后立即发布误报冲突。HTML 清洗保留安全相对图片/链接、表格列宽、合并单元格、表头色与斑马纹 class；脚本和危险 URL 仍会被清除。完整接口映射见 [HR 编辑器接口迁移](portal-hr-editor-api-migration.md)。

## OA 页面与交互适配复查

本轮检查两组管理入口全部页面，统一标题、筛选、列表、固定操作列、次操作菜单、空态与移动布局。培训/品牌/分类菜单保留全部操作；合同增加分区导航与生成前核对；庆祝文案按场景分组，尊重不参与庆祝偏好；简历按待校对/未保存状态突出当前主操作。物资规格和合同主体兼容 OA 字符串 ID。

角色授权增加搜索、分组、已选数及仅看已选；AI 功能支持手机选择器、提示词生效内容查看及载入编辑，切换未保存配置会明确确认；批量导入增加文件拖放、前置格式/大小检查及三步状态。内容编辑复用完整 TipTap 富文本，保存前等待各段落的图片上传，禁止将 blob 临时地址写入数据库。

原设计 CSS 不再向 body 注入字体/通用 reset，旧动画全部独立命名。OA 弹窗的入场缩放修复重复位移，冷打开和先访问 HR 后打开的 16 组浅/深色、桌面/手机组合均验证四边不裁切。

签收看板使用单独的已发布制度元数据接口，统计人员不需要 HR 草稿编辑权限，也不会读取草稿正文。默认先加载制度选项再统计，优先在线的正式制度；下架制度和历史版本只查看/导出，不给不可用的催签入口。统计兼容旧签收别名，按本次在职、主/兼任部门目标集合去重计数。无可用正式 CMS 版本的固定旧制度仍可核对静态历史签收，普通未知标识不降级；不可用 CMS 别名不能借此催签。

## 管理入口分批上线

系统管理员可从「后台管理 → 入口上线管理」进入 `/portal/rollout`，统一配置本批迁移的 20 个业务入口。支持逐项或整组调整、待保存差异、撤销修改和离开未保存提醒；点击「保存上线设置」后才对所有用户生效。当前默认全部开启，沿用迁移后的现状，新增环境也不会自动关闭既有功能。

配置存储于 PostgreSQL `portal_entry_rollout`。保存使用版本号防止多位管理员互相覆盖，并记录变更审计；只有系统管理员能读取维护界面和保存设置，不能通过角色能力矩阵转授此权限。每次进入页面或窗口重新获得焦点会更新菜单状态，管理员保存后自己的导航立即刷新。关闭后侧栏与管理中心隐藏相应入口，HR 编辑/预览等深链同样提示尚未开放；样品与办公用品虽然共用页面，但开关独立。

「管理中心」与「入口上线管理」固定保留以便恢复。读取开关失败时可重试或进入设置修复，不展示未确认的业务入口。开关与原角色权限同时生效，不增加授权；它控制管理页面的开放，不修改员工展示内容、业务数据、业务 API 授权或自动任务。已打开的编辑页面不被强制卸载，下次进入时再检查状态。

PostgreSQL 初始版本已包含入口上线表及默认设置，新环境按统一迁移流程初始化即可；后续发版由 Flyway 记录已执行版本并保留已保存的状态。前后端必须同步更新。前端回归命令为 `npm run test:portal-rollout`，后端覆盖默认值、管理员边界、输入校验、部分更新、并发冲突与无变更保存。

## 数据迁移与核对

Portal 源库与 OA 目标库均为 PostgreSQL，通过各自配置指定连接；源库只读。迁移保留 ID，重复执行跳过已有行；物资归档批次元数据和首次默认庆祝设置另有受限补迁逻辑。导入完成后推进目标 identity 序列，避免新增数据与保留的历史 ID 冲突。

源数据盘点包括：26 门课程及 265 个课时、59 个展会、56 份 HR 文档、126 个物资商品及 187 条规格、130 张物资单据与 140 条明细、19 条 AI 模型、280 条 API 调用、6 份品牌手册索引、2 个合同主体、4 份简历、1 个面试流程与 3 轮面试、12 张贺卡及 55 条原推送审计。该次盘点中新品与制度签收均无记录。新目标库完成正式导入后应重新核对行数及关键关联，初始版本不含这些业务记录。

旧库 5 个主文档已经缺失，但仍有发布或草稿快照（文档 ID 76、77、79、80、90）。迁移在回收站增加仅供历史索引的 5 条归档记录；原快照保持不变，不重新发布。索引注明本次迁移的归档时间，不能当作原文档删除时间。

源库引用的 6 份品牌手册及 4 份简历原件在本地上传目录缺失，当前没有可用的 GCP 访问或本地备份。这些记录和原始引用已保留，文件读取会明确提示原件未迁入。HR 文档 ID 6 另有一张遗留图片 `images/b2e2421af8b6.png`，本地缺失且对应公开 GCS 对象返回 404，仍保留原引用。不能以生成内容代替原件。

另有 7 条原智能排版任务（6 条成功结果、1 条失败记录），迁移保留提交人、原文、结果和时间；正式导入后可用重复 dry-run 核对全部跳过，不触发 AI 调用。

## 新环境的执行顺序

先按[后端 README](../README.md#3-建表与初始数据)，用 Flyway 执行
`src/main/resources/db/postgresql/migration/` 下全部版本。初始结构包含系统、身份、内容及本页全部管理域；
初始种子包含字典、角色、权限和开发管理员，无需额外按模块执行建表脚本。
物资外键、在役商品/规格唯一约束及显式归档批次同样包含在初始结构中，防止独立下架的规格被商品恢复误带回。

依次对以下脚本执行 `--dry-run`，核对后去掉该参数正式迁移：

```text
scripts/migrate_portal_training.py
scripts/migrate_portal_events_products.py
scripts/migrate_portal_hr_documents.py
scripts/migrate_portal_signoff.py
scripts/migrate_portal_materials_ai.py
scripts/migrate_portal_management.py
```

排版历史另执行 `scripts/migrate_portal_hr_layout_jobs.py --dry-run`，核对后用 `--apply` 写入（该脚本默认只读，与上方脚本的正式执行参数不同）。保留任务 ID、提交人、原文、成功结果和真实时间；同 ID 不同内容时拒绝覆盖并回滚。

附件另行执行 `migrate_portal_management.py --copy-assets`；可指定 `--portal-upload-root`、`--document-root` 和 GCS 桶。`--require-all-assets` 会在缺失任何附件时拒绝写入数据库。历史简历只能从私有桶读取。

## 部署配置与切流

- `PORTAL_DOCUMENT_ROOT`：可写持久卷，存放私有原件、图片与贺卡；不要提交该目录。
- `GEMINI_API_KEY` 或 `cyt.ai.gemini-key`：Gemini 环境密钥。
- `AI_KEY_ENCRYPTION_KEY`：Base64 编码的 32 字节 AES 主密钥。旧密文格式兼容，需使用原主密钥；原开发库若使用 JWT 派生密钥，也需对应原派生值，不能换一把密钥后期待旧密文可读。
- `PORTAL_PUBLIC_BASE_URL`：OA 公共基址，生成贺卡分享链接。
- `PORTAL_DISPLAY_BASE_URL`：员工展示门户基址，推送中的新闻/HR 文档链接指向这里。
- `PORTAL_CARD_FONT`：贺卡中文字体路径，部署镜像需提供中文字体。
- `cyt.portal.celebrations.scheduler-enabled=true`：显式启用 OA 庆祝调度。先停旧 Portal 同类任务，再开启，避免重复推送。
- 企微消息继续使用 common-api 网关。现有网关提供文字/Markdown；图片贺卡通过文字消息发送分享链接，不声称发送了网关未支持的原生图片消息。

旧 Portal 前端新增 `VITE_OA_CONSOLE_BASE_URL`。开发默认 `http://localhost:4810`；生产显式设置 HTTPS OA 前端基址并重建后，旧管理路由在原权限检查通过后跳到 OA。兼容 `.html` 及编辑预览深链，仅携带允许的业务参数，不传递 token、OAuth code 或任意回跳 URL。生产不设置该值时保留旧入口，便于分批切流和回滚；切流后不要继续同时在两边编辑同一批数据。

## 验证范围

前后端类型检查/构建、后端单元测试、管理接口只读联调、迁移幂等与外键核对、浏览器 mock 操作、390px 和深色布局、旧入口跨站切流均需通过。推送、AI 厂商调用和真实业务写入不能为界面验收而自动触发。

本机验收不等于生产发布；本批未部署生产。

入口上线管理需覆盖开关保存、分组调整、关闭后的深链拦截、共享页面的独立开关、权限边界、未保存离开提醒、撤销、手机布局及读取失败重试。实际 PostgreSQL 服务联调还应核对无变化保存不增加版本号、既有上线状态不被重置。

编辑器需覆盖 20 类块插入、草稿恢复/删除、排版应用/撤销、新建失败保留、跨文档切换、富文本链接/表格/图片保存、大纲/分栏/预览/设置，以及四种固定旧签收别名查询。角色筛选、AI 未保存切换确认、导入拖放、移动布局与 Portal 切流同样需要回归。后端执行 `mvn package`，前端执行 `npm run build` 和相应业务回归脚本；PostgreSQL 与搬迁脚本的隔离数据库测试方式见[开发说明](development.md#测试)。AI 上游、真实推送及缺失原件需独立验收。
